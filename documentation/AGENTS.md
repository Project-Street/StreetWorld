# 文档写作约定

文档按 `DOCUMENTATION_OUTLINE.md` 的章节组织，组件 API 以 `API_CLASS_FUNCTIONS.md` 为清单，行为和配置取值以当前源码为准。用户后续的修改优先。

`README.md` 提供语言入口。中文版入口为 `DOCUMENTATION_ZH.md`，英文版入口为 `DOCUMENTATION_EN.md`；两者保留相同的章节目录。正文分别放在 `zh/` 和 `en/`：`getting-started/` 保存安装和运行示例，`guides/` 保存架构、接口和配置说明，`reference/` 按组件分组，`launchers/` 保存通用启动流程及每个模型的独立页面。API 清单分别为 `API_CLASS_FUNCTIONS.md` 和 `API_CLASS_FUNCTIONS_EN.md`。

## 文字

- 先写具体操作或行为。使用“调用”“返回”“创建”等动词，少用“赋能”“提升”“充分发挥”“至关重要”等空泛说法。
- 首页介绍软件用途，操作页给出条件和步骤。编写范围、函数收录规则和校对过程留在编写约定中，不在正文开头解释作者怎么写文档。
- Installation 按环境要求、安装命令和检查命令组织。命令连续列出，只补充执行所需的信息；数据目录放到数据页，模型环境放到 Launcher 页，不逐个解释依赖包的用途，也不解释导入成功等常识。
- 运行示例先说明读者用它完成什么、脚本承担哪些工作、何时应选择这个入口，再给出命令。步骤应覆盖必要输入和启动后的操作，说明读者会看到什么；不把“运行脚本以启动某功能”当作用途介绍，也不先抛出内部类名和配置术语。快速运行的顺序为安装、浏览器驾驶、Environment Server、Expert iLQR。
- 改稿先删无用内容，再调整句子。删掉预告、重复总结和空过渡，说明功能时写清谁做什么，避免名词层层套叠。
- 同一个概念使用同一个名称；Environment、SimulatorInterface、AgentManager、Observation、Policy、Controller 各有所指，不轮换近义词。
- 用平常的中文解释技术细节。句子长短取决于内容，不强凑排比、三段式、正反对照或结尾总结。
- 写清默认值、单位、输入形状、实际条件和结果。遇到未实现或未接入的接口，指出具体代码状态，不编造功能、链接或运行结果。
- 文档正文不放“下面为你介绍”“希望有所帮助”、自夸、聊天回应和写作过程说明。
- 不为模仿人类写作而加入错字、随意插话、情绪或虚构经历。
- 按含义判断术语，保留“闭环仿真”等有确切含义的专业词。不能靠替换黑名单词语代替逐段编辑。

这些用词和语气要求参考 [Microsoft 的用词检查表](https://learn.microsoft.com/en-us/style-guide/checklists/word-choice-checklist) 和 [Google 的技术文档语气指南](https://developers.google.com/style/tone)。

中文改稿另参考[中文去 AI 味指南](https://github.com/ninehills/public-skills/blob/main/deslop-zh/SKILL.md)和[中文技术文档规范](https://zh-style-guide.readthedocs.io/zh-cn/latest/语言风格/简洁清晰.html)。这些资料用于编辑判断，具体格式仍按本项目约定。

## 格式

- 宏观说明用连贯段落；命令用代码块；配置和 API 查询用表格。相同用途的内容必须采用相同格式。
- 总目录、分组目录和页内目录统一使用缩进列表，一项对应一个章节或页面。标题与正文一致，编号连续，链接指向相应文件或小节；不把目录做成表格，不附加每章内容摘要，也不在同一层重复列出章名。
- 每个组件固定使用“职责与创建方式”“配置”“API”“使用示例”四个小节，顺序不变。“职责与创建方式”先说明这个类是什么、解决什么问题以及何时使用，再介绍创建方式、组件关系和必要的使用条件，不以继承关系或内部字段开头。没有独立配置的组件明确写出来源；没有本类 API 的组件不补列纯继承成员。
- 配置表固定为“字段｜类型与单位｜默认值｜用途与生效条件”；完整键路径写在字段列中。
- API 表固定为“类别与签名｜参数｜返回值｜行为与调用条件｜异常与实现状态”。仅列本类定义或覆写的成员；双下划线内部私有方法不列出。
- 列表用于步骤或真正并列的项目，不把每句话拆成项目。不用 emoji 装饰标题，不机械加粗，不用破折号串起多重补充说明。
- 每个 Policy Launcher 使用同一套栏目，命令中的路径必须与对应加载器一致。
- 每页提供总目录、上一页和下一页链接；组件页提供类名索引。跨页引用必须指向对应文件或锚点，源码链接按页面所在目录计算相对路径。
- 中英文正文一一对应，每页提供另一个语言版本的链接。修改配置、签名、行为或示例时同步更新两个版本；命令、参数名、默认值与显式锚点保持一致。英文组件小节统一为 Purpose and construction、Configuration、API、Example，配置与 API 表保持与中文版相同的列结构。

格式检查还参考 [Wikipedia 的 AI 写作特征说明](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)。该页面记录的是常见现象，具体格式仍按本项目要求决定。

## 校对

先核对源码、参数、表格和链接，再通读正文。删除没有提供新信息的句子，修正重复模板语、空泛修饰和不必要的对照句。读出句子，检查语序、指代和信息顺序是否自然。不能用润色掩盖事实缺口。
